## 1. Madhya Pradesh & Indore Government Source Investigation (Part 5)

In strict compliance with Part 5 ("Never bypass authentication, CAPTCHA, access restrictions, or terms of use. Never pretend that an unofficial source is an official government API. Never fabricate government records."), below is the verified assessment of each relevant Madhya Pradesh and Indore government authority:

| Government Authority | Official Domain | Responsible Department | Public / Partner API Availability | Auth & Access Requirements | Permitted Data Fields & Usage | Integration Strategy in PropVault |
|---|---|---|---|---|---|---|
| **1. MP Bhulekh (Land Records)** | `mpbhulekh.gov.in` | Commissioner Land Records & Settlement, Govt. of Madhya Pradesh | Public citizen portal is gated by session tokens & CAPTCHA. Official Webline/API access is restricted to authorized government departments, banks, and licensed institutional partners via MPSEDC / CLR approval. | Institutional MoU / API credentials issued by CLR Gwalior / MPSEDC. | District (`Indore`), Tehsil, Village, Khasra Number, Khatauni / B1 Landowner Name, Land Area (Hectare), Land Use / Diversion status. | **Status: `Blocked by external dependency` (Pending CLR Partner Credentials).**<br>Implement `MPBhulekhAdapter` supporting:<br>• `LIVE_API` mode when partner credentials (`MP_BHULEKH_API_KEY`) are configured.<br>• `PENDING_AUTHORIZATION` / Structured Manual Verification mode where a licensed Verifier/Advocate records the official MP Bhulekh Khasra Reference Number, Tehsil, Village, uploaded certified copy, retrieval timestamp, and provenance status (`GOVERNMENT_VERIFIED` only when backed by official digitally signed certificate or live API; otherwise `PLATFORM_VERIFIED` / `VERIFICATION_PENDING`). |
| **2. MP RERA** | `rera.mp.gov.in` | Madhya Pradesh Real Estate Regulatory Authority | Public search pages exist for registered projects & agents, protected against automated scraping. No open unauthenticated REST API is published for third-party commercial platforms without RERA data-sharing authorization. | Official partner API authorization or manual verification against MP RERA registration number (`P-IND-...` / `A-IND-...`). | RERA Registration Number, Project Name, Promoter/Builder Name, Registration Validity Date, Approved Units, Project Status, Revocation/Default status. | **Status: `Blocked by external dependency` (Pending MP RERA API Access).**<br>Implement `MPReraAdapter` recording RERA Registration ID, official verification URL (`https://rera.mp.gov.in/`), promoter name, validity date, verifier sign-off, and provenance timestamp. |
| **3. Partner APIs are restricted to licensed Service Providers / Banks. | Licensed SAMPADA Service Provider / Departmental API key. | e-Registration Document Number, Sub-Registrar Office (`Indore-1..4`), Execution Date, Stamp Duty Paid, Guideline Value per sq.m/sq.ft, Encumbrance search period. | **Status: `Blocked by external dependency` (Pending IGRS SAMPADA API Credentials).**<br>Implement `MPIGRSSampadaAdapter` to record Sub-Registrar Office, Registered Deed Number, e-Stamp Serial Number, Search Period (13/30 years), and Advocate Title Search sign-off with full provenance metadata. |

MP Town & Country Planning (T&CP)** | `mptownplan.gov.in` | Directorate of Town and Country Planning, Govt. of Madhya Pradesh | Layout approval and Master Plan land-use permissions are processed via MP-ABPAS (`abpas.mpurban.gov.in`); no open third-party REST API. | Manual verification of T&CP Layout Approval Letter / ABPAS sanction number. | T&CP Sanction Number, Sanction Date, Approved Land Use (Residential / Commercial / Industrial / PSP), FAR / Colony layout reference. | **Status: `Not available as public API` (Manual Provenance Workflow).**<br>Implement `MPTNCPAdapter` for recording T&CP Sanction Letter Number, Approved Land Use, and provenance metadata. |

## 2. Internal Frontend ↔ Backend API Contract Audit

| Endpoint | Method(s) | Backend Status | Frontend Consumer | Contract Discrepancies Found |
|---|---|---|---|---|
| `/api/v1/auth/register/` | `POST` | Functional | `RegisterPage.tsx` | Returns `dev_otp` unconditionally in JSON response; must be restricted to `settings.DEBUG = True`. |
| `/api/v1/auth/verify-otp/` | `POST` | Functional | `RegisterPage.tsx` | `auth.types.ts` defines purpose `'RESET'`, while backend `OTPPurpose` expects `'RESET_PASSWORD'`. |
| `/api/v1/users/kyc/submit/` & `/status/` | `POST`, `GET` | Functional | `KYCPage.tsx` | Missing admin endpoint (`POST /api/v1/users/kyc/<id>/review/`) to transition `KYCRecord` from `UNDER_REVIEW` to `APPROVED` or `REJECTED` and set `User.is_verified = True`. |
| `/api/v1/properties/` | `GET`, `POST` | Functional | `SearchPage.tsx`, `CreatePropertyPage.tsx` | **Broken Contract on `POST`**: `CreatePropertyPage.tsx` submits `carpet_area_sqft`, `super_builtup_area_sqft`, `bhk_count`, `amenities`, and `property_type` values `COMMERCIAL_SHOP` / `AGRICULTURAL_LAND` / `PENTHOUSE`. Backend `PropertyCreateUpdateSerializer` requires `built_up_area`, `carpet_area`, `bedrooms`, `amenities_list`, and enum values `SHOP` / `AGRICULTURAL` / `VILLA`. |
| `/api/v1/properties/<id>/` | `GET`, `PATCH`, `DELETE` | Functional | `PropertyDetailPage.tsx` | **Privacy Breach on `GET`**: Public unauthenticated `GET` returns full `PropertyDocument` file URLs and `PropertyOwner` user emails/phones. |
| `/api/v1/properties/<id>/documents/` | `POST` | Functional | `property.service.ts` | `property.service.ts` appends form field `file`, whereas backend `PropertyDocumentUploadSerializer` expects `document_file`! Furthermore, `CreatePropertyPage.tsx` never calls `uploadDocument`. |
| `/api/v1/listings/**` | `GET`, `POST`, `PATCH`, `DELETE` | Functional & Tested (23 tests) | `BrowseListingsPage`, `ListingDetailPage`, `MyListingsPage`, `ListingEditorPage`, `ListingModerationPage` | Contracts match and are verified by automated tests. |
| `/api/v1/verification/**` | `GET`, `POST` | Functional | `VerificationPage.tsx`, `PropertyPassport.tsx` | Lacks provenance fields (`authenticity_level`, `source_authority`, `source_reference`, `verification_method`, `retrieved_at`, `freshness_expires_at`). |
| `/api/v1/discovery/**` | `GET`, `POST` | Functional in backend | **None** | Saved Searches and Favorites endpoints are not wired to any frontend button or page. |
| `/api/v1/leads/**` | `GET`, `POST`, `PATCH` | Functional | `LeadsPage.tsx`, `PropertyDetailPage.tsx` | Missing agent assignment and follow-up interaction history endpoint. |
| `/api/v1/visits/**` | `GET`, `POST`, `PATCH` | Functional | `VisitsPage.tsx`, `PropertyDetailPage.tsx` | Frontend `VisitsPage.tsx` lacks Reschedule and Feedback Rating modals. |
| `/api/v1/negotiations/**` | `GET`, `POST` | Functional & Tested | `TransactionsPage.tsx`, `PropertyDetailPage.tsx` | Missing offer expiration (`expires_at`) enforcement. |
| `/api/v1/transactions/**` | `GET`, `POST` | Functional | `TransactionsPage.tsx` | `TransactionMilestoneView` auto-marks payments as `SUCCESS` without requiring payment gateway signature or escrow UTR verification, and lacks `TransactionTask` checklists. |
| `/api/v1/payments/**` | `GET`, `POST` | Partial | `TransactionsPage.tsx` | Needs proper 2-step order initiation (`INITIATED`) → signature/UTR verification (`SUCCESS`) flow. |
| `/api/v1/builders/**` | `GET` only | Read stub | **None** | Missing write endpoints, unit inventory model, and Builder dashboard UI. |
| `/api/v1/investments/**` | `GET` only | Read stub | **None** | Missing write endpoints and Investor dashboard UI. |
